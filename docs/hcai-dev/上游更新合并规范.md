# HCAI 上游更新合并规范

目标：引入指定上游版本，同时保留 HCAI 的全部有效定制。参考 [v0.2.7 冲突记录](../UPSTREAM_0.2.7_HCAI_MERGE_CN.md)。

## 1. 固定基线

合并前记录本地/远程 dev、main 的 SHA、当前 HCAI 版本、上游标签及其解析后的 SHA。确认 origin 为 WangYa-Technology/sub2api，upstream 为 Wei-Shaw/sub2api。先处理或隔离已有修改，不覆盖他人工作区。

```bash
git status --short --branch
git remote -v
git fetch origin
git fetch upstream --tags
git rev-parse origin/dev origin/main
```

这些命令只是基线检查。随后核实目标标签、Release 说明、升级跨度和迁移，不以“最新”或网页标题代替不可变 SHA。若目标版本未发布，停止并确认是否接受其他版本，禁止静默更换。

从更新后的 dev 基线新建 chore/sync-upstream-版本 分支。使用确认的上游 SHA 执行 git merge --no-commit --no-ff，保留合并关系；不要把整个上游目录复制覆盖 HCAI。

## 2. 冲突处理

每个冲突逐 hunk 阅读两侧目的，不能批量 ours/theirs：

| 范围 | 处理原则 |
| --- | --- |
| 首页与静态资源 | 保留 HCAI 品牌资源、加载态、主题和入口；合入上游必要门控 |
| 设置链路 | HCAI 汇率、插件开关与上游新增字段共同保留，验证保存后重新读取 |
| 模型广场 | 保留渠道展示优先和官方独立来源，保护真实扣费优先级 |
| 菜单 | open_mode 与 hide_open_button 并存；跨域无凭据 |
| i18n | 两侧有效键合并，中英文对齐，删除调用点前不删文案 |
| Wire/生成代码 | 从源定义和构造函数核对依赖，优先按项目生成流程更新；手工修复需说明和验证 |
| 依赖锁文件 | 按工具链解析依赖，不能简单拼接；检查冻结安装及模块校验 |
| 数据库 | 按完整迁移文件名核对，同数字文件不可直接判重；保护已发布校验与兼容性 |
| 测试 | 保留两侧行为覆盖，不能只删失败断言或改 fixture 掩盖回归 |
| 发布/README | 保留 HCAI 仓库、版本、文档及工作流，不恢复上游广告/默认安装入口 |

v0.2.7 曾遗漏限流服务的 Ollama 依赖、插件 KV 注入及 RedeemService 测试参数。合并不报文本冲突不代表接口兼容，所有构造函数调用均需复核。

## 3. 无文本冲突也必须审查

使用 [自定义清单](HCAI自定义功能清单.md) 与 [文件附录](HCAI全量差异与提交附录.md) 逐模块检查。分别对比“合并结果与旧 HCAI”以及“合并结果与目标上游”，记录新增上游能力、净定制差异和被吸收的历史修复。

必须覆盖首页/插件开关、模型广场/翻译、CC Switch、兑换码返利、沙箱支付、外链安全、上游账户探测、异步图片/MinIO、企业微信、节点指标、后台作业锁/刷新租约/认证失效广播以及 CI。不得只搜索 hcai 字符串。

## 4. 验证与合入

执行 [开发规范](开发规范.md) 全部 CI 等价检查，并做内嵌前端构建。迁移和多节点测试在独立环境执行；模型广场用“同时有渠道价和分组价”的数据验证展示，再确认真实计费未变。

本地测试不能替代 PR 最终 head SHA 上的两项必需检查。CI 失败先修复并重新运行，不能在必需检查失败、取消或缺失时发布。生成合并记录后先 PR 到 dev，再按授权创建 dev → main 发布 PR；是否合并、创建 Release 或部署按单独授权和发布规范执行。

## 5. 每次必备记录模板

新记录保存为 `docs/hcai-dev/上游合并记录-<版本>.md`；已有历史记录保留原路径并引用。按 [开发规范](开发规范.md) 第 5 节同步自定义清单、差异附录及受影响规范；单次记录必须可追溯：

```text
HCAI 基线 SHA / 版本：
上游标签 / SHA / Release URL：
目标 HCAI 版本：
合并提交 / PR：
显式冲突数量：
文件 | 冲突双方意图 | 采取方案 | 保留行为 | 验证
无冲突但存在语义变化：
被上游吸收或废弃的定制及依据：
新增迁移 / 配置 / 依赖：
命令 | 测试提交 SHA | 结果 | 日志链接
未验证项 / 风险 / 是否阻断：

```

零冲突也要提交记录。前次测试通过不能自动代表本次通过；如果测试中断，补记后续 CI 结果与修复，不抹去失败事实。
