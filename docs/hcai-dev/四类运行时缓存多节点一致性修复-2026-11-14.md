# 四类运行时缓存多节点一致性修复

日期：2026-11-14。基线：0.2.21-hcai 工作树及此前未提交的 HTML/CSP 跨节点失效修复。授权：修复审查发现的四类问题；仅本地代码、测试与文档，不连接生产、提交推送、发布或部署。保留此前其他任务的审查/发行文档修改。

## 问题与解决

| 问题 | 当前实现 |
| --- | --- |
| IP 信任开关/请求头列表只有保存节点更新 | 设置通知、订阅恢复及30秒补偿中重新读取DB，只更新本机Config原子快照；不执行启动历史迁移、不写库、不重发 |
| WebSearch Manager 只在本地保存时重建 | 独立保存入口落库成功后发布 websearch.updated；各节点直读DB并解析代理，配置或代理URL变化才重建Manager |
| 错误透传规则丢通知后长期旧值 | 通知及订阅确认触发DB重载，30秒定时直接DB重载兜底；不依赖旧本地/Redis规则快照 |
| TLS指纹模板丢通知后长期旧值 | 与错误透传相同，独立worker与现有channel；服务Stop取消并等待worker/订阅退出 |

历史发现和优先级保留在[审查记录](多节点进程缓存一致性审查-2026-11-14.md)，下文为本次实现后的新状态，不把旧审查改写成从未存在问题。

## 设置运行时同步

沿用 `sub2api:settings:updated:v1`。JSON仍只有 `type/node/version/time`，新增允许类型 `websearch.updated`；通用系统设置保存仍是 `settings.updated`。不发布API Key、代理URL、头列表或其他设置值。接收后仅失效HTML/CSP并直读DB刷新两类运行时状态，不调用保存回调。忽略本进程事件，重复/乱序只读取当前数据库，不会回写旧设置或产生通知回环。

客户端IP运行时读取不调用 `LoadForwardedClientIPSettings`，因为该启动函数包含旧配置迁移写入。新增只读方法与本地保存的Config写入共享mutex；正常读取显式开关/头列表，读库或头解析失败时禁用转发头信任，等待后续通知/补偿恢复，不在失败时扩大信任。

WebSearch独立保存只在写库成功后通知；发布失败仅Warn，不能影响已落库保存成功。本机先按DB重建，其他节点收到通知从DB读取。读取Manager配置不命中60秒TTL旧缓存；同时更新轻量入口配置缓存。基于配置和代理URL的SHA256指纹避免每个设置事件/30秒校准都重建HTTP客户端。指纹不输出到日志，原始配置和凭据不发Redis。

配置DB读取失败时清空本机Manager并置未完成标志，避免在已经变更但不可确认时继续使用旧Key；后续校准成功会重建。代理查询失败时维持现有builder的安全行为：声明了代理但无法解析的供应商被跳过，不静默直连。代理修改本身未新增发布入口，通过30秒有效配置校准捕获URL变化；这不是代理变更即时生效保证。

本次同时修正部分设置保存已成功、随后读取整份设置失败时不触发onUpdate的漏通知路径：仍会失效/通知并在后续补偿中重载。未将所有其他TTL设置缓存改为全域即时同步。

## 规则与模板订阅/补偿

保留现有channel：`error_passthrough_rules_updated`、`tls_fingerprint_profiles_updated`，消息仍为 `refresh`。复用现有注入Redis客户端，只创建PubSub连接。

repository增加共用可关闭订阅封装：连接丢失记录Warn并重试，收到初次/重连subscription确认也请求重载，context取消主动关闭PubSub并等待退出。两缓存适配器提供可管理订阅能力，原SubscribeUpdates接口仍兼容已有调用者。

service增加共用校准worker：通知合并入容量1的唤醒队列，串行处理刷新；每30秒另作兜底。回调与定时器都直接从PostgreSQL加载并回填本地/Redis缓存，不经过缓存Get，故Redis旧快照或DEL失败不能阻止更新。接收不会调用NotifyUpdate。DB失败保留既有运行快照并Warn，后续定时重试；不假装失败时已与DB一致。

两个服务的DB重载各有mutex，避免多个刷新并发完成顺序倒置。worker使用5秒读取context。Stop幂等，取消worker并停止/join生产Redis订阅；Wire源文件、生成文件及cleanup测试参数同步更新，先停止业务订阅再关闭基础设施。无Redis客户端的缓存适配器使用本地缓存，Get/Set/Invalidate/Notify不因nil客户端panic。

正常环境下广播即时驱动；Pub/Sub没有持久化重放，30秒是补偿调度周期，不是数据库/网络故障下的最大一致性SLA。没有增加数据库迁移、公开清缓存接口、第二套Redis客户端或真实上游调用。

## 验证记录

使用Go1.27.3、miniredis与本地线程安全repository测试桩，无真实数据库或付费调用。miniredis断线/重启仅限隔离测试进程，不是生产或应用服务重启。

- 新增双节点独立Config：A保存信任开/关、头列表，B接收更新；WebSearch独立保存后B启用、更换供应商/Key、关闭；重复通知不重建相同Manager，事件不含Key。
- IP读库失败/非法头格式时fail closed，恢复后读库生效；WebSearch读库失败后恢复，代理URL变化和代理解析失败/恢复。
- 无Redis与发布失败时WebSearch保存成功、写库失败不替换本地运行时。
- 使用生产缓存适配器与实际service的双节点规则/TLS测试：旧Redis L2数据仍存在时事件触发直读DB；断线期间DB变化后重连自动更新；通知时DB失败，恢复后无第二次通知仍在定时校准恢复；重复通知、Stop幂等及订阅数归零。
- 无Redis客户端规则/TLS本地模式及订阅无法连接时及时取消。

初次新增IP测试因期望未采用HTTP头标准大小写而失败（X-New-IP被现有规范化转为X-New-Ip），已改为正确期望；不改正常化行为。最终命令与结果见下表，未隐藏初次期望错误。
