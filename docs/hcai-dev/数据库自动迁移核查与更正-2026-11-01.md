# 数据库自动迁移核查与更正

核查日期：2026-11-01。适用证据：上游 v0.2.16、v0.2.18 及本次 0.2.19-hcai 合并结果。

## 明确结论

正常服务启动会自动执行数据库 SQL 迁移。此前审查中“普通启动不执行迁移、需要依赖外部脚本”的判断错误，原因是只检索了导出函数 `ApplyMigrations`，遗漏实际启动直接调用的小写 `applyMigrationsFS`。不能以生产演练未完成推导出系统没有自动迁移能力。

## 代码证据

- `backend/internal/repository/ent.go`：`InitEnt` 创建 10 分钟迁移上下文，通过 `initializeDatabaseWithRetry` 调用 `applyMigrationsFS(ctx, drv.DB(), migrations.FS)`；失败关闭连接并返回错误。
- `backend/internal/repository/migrations_runner.go`：以完整文件名及校验和跟踪迁移，PostgreSQL advisory lock 序列化多实例迁移；已执行项目跳过，非事务迁移另行处理。
- `git show v0.2.16:backend/internal/repository/ent.go` 与 v0.2.18 同一路径均在第 139 行调用该函数；因此不是 0.2.19 才引入自动迁移。
- 本次 `hcai_0219_migration_test.go` 使用相同迁移核心在隔离 PostgreSQL 17 验证旧基线升级、247/248 生效及重跑幂等，通过。

## 证据范围

代码证明正常启动机制，隔离测试证明本次迁移可在该测试环境执行；二者不代表已读取四个生产节点的 schema_migrations，也不能代替生产备份恢复验证。本次不进行部署，不虚构历史每台节点迁移日志或执行时间。

历史文档的原始快照保留，本更正记录取代其中关于“无自动迁移”的结论。
