# HCAI 版本发布规范

适用仓库：WangYa-Technology/sub2api。发布不是部署；main 合并、Release 和生产上线分别核验。代码基础见 [.github/workflows/amd-linux-release.yml](../../.github/workflows/amd-linux-release.yml)。

## 1. 版本标识

上游 X.Y.Z 首次集成使用 X.Y.Z-hcai；VERSION 文件不含 v，Git 标签和 Release 为 vX.Y.Z-hcai。同一上游基线的 HCAI 后续发布建议使用 X.Y.Z-hcai.1、.2 等唯一编号，不复用已发布版本。

增量后缀是本规范的后续发布约定，并非已验证所有工具的排序兼容；采用前测试 resolve-version、前后端版本展示和更新比较，不能把“有新后缀”直接等同自动升级提示。当前 update service 仍有上游来源，Release 页面与构建信息才是 HCAI 产物核查依据。

resolve-version.sh 优先读取当前提交的精确 Git 标签，其次 VERSION。发布前必须比对文件、脚本解析结果、目标标签，禁止出现旧标签覆盖新文件版本。

## 2. 当前自动化与风险

当前工作流在非纯 Markdown 的 push main 或 workflow_dispatch 时触发；仅 main 允许进入发布门控。门控读取 VERSION，目标标签已存在则跳过构建和发布，保留旧标签与附件；新版本还必须与 resolve-version.sh 解析结果一致。随后构建前端、Linux amd64 内嵌程序、归档及校验信息，使用非强制 tag/push 创建标签并发布附件。

2026-09-19 的文档发布任务增加了 Markdown 路径过滤、已有标签跳过及非强制推送保护。发布工作流仍不会重新运行完整 CI，以下人工核验仍然必须执行：

- 只修改 Markdown 的 main 推送不触发发行；混入工作流或其他文件会触发门控。未提升版本的变更若命中已有标签会跳过发布，不代表产生了新产物。
- 已对外发布的标签和附件不重指、不覆盖。发现重名立即停止；不能以重新跑 workflow 作为无影响操作。
- 手动 workflow_dispatch 只允许经批准的 main 发布提交，不从任意功能分支发布。
- 发布失败可能留下标签或部分附件；先查远程实际状态，再制定恢复方案。优先新版本，不盲目重跑覆盖。
- 工作流带 cancel-in-progress，新推送可能取消在途发布；一个发布完成前不并发推进另一次 main 更新。

历史 v0.2.7 发布流程曾强制移动同名标签；历史清单按原基线保留，不用新规则倒写旧记录。首次合入本次保护时必须核查 release-gate 日志及原标签/附件是否保持不变。

## 3. 发布门槛

1. dev 合入完成，版本、迁移和自定义清单已更新，工作区无混入改动。
2. dev → main PR 写明范围、测试 SHA、合并记录、升级要求、回退条件和 Release Notes。
3. 最终 PR 提交上 Backend checks、Frontend checks 均成功，审查通过且无未解决阻断项。任何实质修改后旧结果失效。
4. 涉及前端必须确认 embed 构建；迁移/支付/多节点按影响完成独立环境验证。
5. 有可用备份、上一版产物和数据库兼容评估。只有“程序能启动”不足以放行。
6. 获得合并/发布授权后才合入 main。工作流启动不等于发布成功。

## 4. 产物核验

等待工作流完成并检查：

| 对象 | 必须一致 |
| --- | --- |
| main 合并提交 | 发布授权的 SHA |
| 标签解析结果 | 指向该发布提交，不是旧 dev SHA |
| VERSION / 解析结果 | 目标 HCAI 版本 |
| BUILD_INFO.txt | 版本、标签、提交前缀、构建时间、linux_amd64 |
| 两个二进制附件 | 解压后内容一致，均为目标架构 |
| checksums.txt | 覆盖归档和 gz 文件，下载后校验通过 |
| Release 状态 | 标题、标签、附件齐全，最新标记与发布策略一致 |

发布包包括 sub2api_<版本>_linux_amd64.tar.gz、sub2api-linux-amd64.gz、checksums.txt、BUILD_INFO.txt。不宣称存在未构建的 arm64 或 HCAI Docker 镜像。发布摘要必须说明包内安装脚本可能仍指向上游。

## 5. Release Notes 模板

```text
版本 / 标签 / main SHA：
上游基线：
HCAI 新增与修复：
上游新增能力：
冲突记录链接：
数据库 / 配置 / 依赖变化：
验证命令与 CI 链接：
兼容风险与已知问题：
部署顺序及监控项：
回滚条件：
产物 / 架构 / 校验文件：
```

不要只使用自动生成的 commit 列表代替迁移和风险说明。保留已知缺陷，不写未经证实的“全部可用”。

## 6. 发布后的状态

依次区分“PR 已合并”“构建成功”“Release 核验完成”“允许部署”“各区域上线完成”。Release 最新不证明生产已更新。每个阶段记录负责人、时间、SHA 和链接。

代码缺陷用新修复提交和新版本解决；线上回退按 [部署规范](部署与多区域运维规范.md) 处理，不通过移动旧标签伪造修复完成。
