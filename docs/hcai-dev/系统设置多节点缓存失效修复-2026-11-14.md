# 系统设置多节点缓存失效修复

日期：2026-11-14。开发基线：本地 chore/sync-upstream-0.2.21，HEAD b4e82103e，基于 0.2.21-hcai。状态：本地实现，待用户审核；未提交、推送、发布、连接生产或部署。既有部署前审查文档改动保留，未混作本次修复。

## 根因与范围

后台系统设置成功 SetMultiple 后执行进程内 onUpdate。原 router 回调仅失效当前 FrontendServer/HTMLCache 并重载 CSP frame-src origins，其他节点没有通知，长期复用注入旧 window.__APP_CONFIG__ 的 HTML。数据库和后台读取新值不代表各进程 HTML 更新。

本次只同步 HTML 注入缓存和 frame origins，不把所有设置热缓存的全局一致性都宣称解决。现有 setting_update.go 已在成功写库后通知，失败写库不调用回调，因此不重写该文件。admin.go 认证/路由保持原样，无新公开清缓存接口，无迁移，无额外 Redis 客户端或依赖。

## 协议与流程

- Channel：`sub2api:settings:updated:v1`。
- JSON：`{"type":"settings.updated","node":"进程UUID","version":"事件UUID","time":毫秒时间戳}`。
- node 每进程实例生成，version 每次保存生成，避免同主机重复实例或重启导致自消息识别混乱。时间/版本只作事件标识，不根据时钟排序更新设置。
- 只发事件元数据，不发布设置值、菜单 URL、密钥、用户信息。

保存流程：SetMultiple 成功 → 原 settings refresh 回调 → 同步失效本机 HTML 并重新读取 PostgreSQL 刷新 frame origins → 使用注入的既有 redis.Client 发布。失败发布仅 slog.Warn，不能把已落库的保存变成失败响应。发布使用独立短 context，实际网络等待仍受既有客户端连接/读写超时及重试配置影响，不承诺所有故障均严格一秒结束。

接收流程：各进程订阅 → 校验 JSON/类型/必要字段及 1024 字节长度限制 → 忽略本实例消息 → 只执行本机失效与重载，不走保存回调、不写设置、不再次发布。重复/乱序事件均重新读取数据库最新值，结果幂等，不按旧事件内容覆盖状态。刷新互斥，避免旧的 origins 读取覆盖后完成的新读取。

无 Redis 客户端时不启动订阅，保留本地同步回调。Redis 暂不可用时订阅报 Warn 并重试；go-redis 在重新建立订阅后返回 subscription 确认，收到确认立即重新校准。由于 Pub/Sub 没有持久化重放，增加每 30 秒只做本地刷新作为补偿，即使发布失败或断线丢通知也不长期保留旧 HTML。此为健康数据库条件下的最终一致性，不是无条件 30 秒内完成的 SLA；数据库读取失败时保留之前 origins、记录 Warn，后续重试。

关闭流程：Application Cleanup 在其他基础设施关闭前调用 StopFrontendInvalidation，取消 context、关闭 PubSub 以唤醒阻塞 Receive，等待订阅/补偿刷新退出。Stop 可重复调用；不关闭共享 Redis 客户端，由原有生命周期处理。Wire 源码、生成文件和 cleanup 测试参数一起维护。

## HTML 并发写回保护

仅广播失效仍有竞态：旧设置查询在失效后完成，可能重新缓存旧 HTML。HTMLCache 增加 Version/SetIfVersion，查询前取代次、写回时校验；代次变更则拒绝缓存旧结果。该次已经进行中的请求仍可能返回其查询快照，但不会污染后续请求缓存。响应 ETag 根据本次渲染内容生成，不取其他并发请求刚写入的 HTML 的 ETag。

## 部署注意事项（仅方案，未执行）

用户本次说明的范围为日本 01、日本 02、美国三节点，共用 PostgreSQL 和 Redis；不沿用此前四节点清单加入台湾或 jp-03。实际部署需后续审核授权，不能把本次修复当作部署授权。

三节点均需运行包含本次修复的二进制，旧版节点不能接收新事件。继续使用现有 Redis 初始化和凭据，ACL 必须允许 PUBLISH/SUBSCRIBE 及本 channel；无需开放 HTTP 接口。Pub/Sub 不按 Redis DB 隔离，同 Redis 上不同部署也会收到事件；事件仅触发各自读库，不携带其他部署配置，但建议环境隔离 Redis，避免无关失效。

补偿每节点每 30 秒重新加载公开设置/来源并清 HTML，会增加少量 DB 查询和按需渲染。不推送浏览器运行时状态；已打开 SPA 仍需重新加载页面/重新拉取设置，不承诺现有页面即时更新。更改后跨三节点分别加载 HTML，验证 custom_menu_items 及 iframe CSP origins；发布故障观察对应 Warn，不以重启所有服务作为同步手段。
