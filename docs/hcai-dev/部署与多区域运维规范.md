# HCAI 部署与多区域运维规范

本文件是上线操作标准，不包含真实服务器地址、密钥或当前在线状态。基于当前源码、历史“日本三个节点 → 台湾 → 美国”的发布顺序和仓库多区域测试环境编写。拓扑和路径必须在发布前核实。

## 1. 部署前发布单

没有以下信息不进入生产操作：

```text
授权范围 / 操作人 / 复核人 / 时间窗：
目标版本 / Release URL / 完整 commit SHA：
附件名称 / SHA-256 / 架构：
上一版版本 / SHA / 原程序或镜像位置：
节点代号 / 主机资产编号 / 区域 / 入口 / 服务名：
配置与数据路径 / 进程启动方式：
PostgreSQL 拓扑 / Redis 数据集与 scope：
数据库迁移及新旧程序混跑兼容结论：
备份时间 / 存放位置 / 恢复验证 / 允许数据损失：
观测窗口 / 错误率和延迟等量化阈值：
真实上游冒烟是否授权及预算：
回退负责人 / 条件 / 方案：
```

如果台湾已完成且用户要求继续美国，核验台湾完成记录后只推进美国，不重复部署。不得擅自扩大节点或顺序；不要为探测版本访问用户禁止访问的业务站点。

## 2. 运行条件与首次初始化

准备目标架构 Linux、PostgreSQL、Redis、非 root 服务用户、持久化目录、TLS 反向代理、时间同步和必要出站网络。限制数据库/Redis只对授权节点开放，校验连接加密、凭据权限及跨区延迟。

配置参考 [config.example.yaml](../../deploy/config.example.yaml)、[.env.example](../../deploy/.env.example)。通过安全配置系统管理 JWT_SECRET、TOTP_ENCRYPTION_KEY 和其他加密密钥；共享认证/加密数据的节点必须使用匹配且稳定的密钥，不能重启随机生成或复制测试密钥。

DATA_DIR 决定初始化配置和 .installed 所在位置；确认服务工作目录、CONFIG_FILE 和挂载路径与已有安装一致。不得误删 .installed 或创建空挂载导致进入全新安装向导。首次安装只从受控入口初始化一次共享数据库，再让其他节点接入；不同时创建多个管理员。

TLS 入口应支持流式响应、WebSocket、合理超时/请求大小；只信任受控反代的转发头。对象存储和异步结果必须能被需要读取它们的节点访问，不能把临时本地图片当跨区域共享文件。

## 3. 获取 HCAI 产物

只用本仓库已核验的 -hcai Release，下载归档、gz、checksums 和 BUILD_INFO 到本次独立暂存目录。在 Linux 下对下载的两个附件执行 sha256sum -c checksums.txt；确认构建 SHA、版本、架构与发布单一致。

包内 deploy/install.sh 和仓库 compose 可能引用上游，不直接执行上游下载/自动更新命令。systemd 示例的 /opt/sub2api、服务名 sub2api 只是参考，必须检查实际 ExecStart、WorkingDirectory、EnvironmentFile、User、可写目录和持久化路径。

容器使用已验证的 HCAI 镜像 digest，不用 latest；本仓库未保证有官方 HCAI 容器发行物。自建镜像需独立验证 Dockerfile 的 pnpm/Node 与锁文件兼容以及 embed 资源，不能用已有二进制 CI 代替镜像构建验收。

## 4. 多区域参考拓扑

以下是计划示例，可能不是当前生产事实：

| 节点 | 区域 | Redis scope | 全局任务 disabled |
| --- | --- | --- | --- |
| jp-01 | japan | japan-shared-redis | false |
| jp-02 | japan | japan-shared-redis | false |
| jp-03 | japan | japan-shared-redis | false |
| tw-01 | taiwan | taiwan-independent-redis | true |
| us-01 | us | us-independent-redis | true |

所有节点连接同一逻辑 PostgreSQL 数据库。日本示例共享一个 Redis 数据集，台湾和美国各用 Redis 独立数据集。同一 Redis 数据集的 scope 必须相同，不同数据集必须不同；不要因不同连接别名把同一 Redis 分成多个 scope。

日本节点配置示意：

```dotenv
OPS_NODE_ID=jp-01
OPS_REGION=japan
API_KEY_AUTH_CACHE_INVALIDATION_SCOPE=japan-shared-redis
GLOBAL_BACKGROUND_TASKS_DISABLED=false
```

其他日本节点仅修改唯一 node_id；台湾/美国改 region、scope 并设 disabled=true。确认 systemd 环境文件或 compose environment 实际传入这些值：仅编辑 .env 不代表应用收到配置。

共享 DB 作业在配置 DB 时由 PostgreSQL 锁权威协调；DB 错误时不回退到区域 Redis 争抢全局 leader。disabled 只限制受该开关控制的任务，不意味着关闭所有本地维护。不同作业可由不同日本实例持锁，不要求全系统唯一一台 leader。

区域 Redis 隔离也不意味着所有限流/并发计数天然全局一致；跨区复用账户时需核实每类计数作用域及总容量，禁止假定全局硬限额。认证缓存失效通过 outbox 和各 Redis scope 消费传播，需要验证失效时延。

## 5. 上线顺序与每节点操作

默认顺序固定为 jp-01 → jp-02 → jp-03 → 台湾节点 → 美国节点。日本首节点作为 canary。每次只更换一台，同一入口保留足够健康容量；若某区域只有一台实例，先确认可迁移流量或批准维护窗口，不能承诺零中断。

每台都执行：

1. 核验节点身份、当前版本、旧程序校验、磁盘空间、依赖健康、配置备份。
2. 从负载均衡摘流，等待在途流式请求、WS 和任务按预案排空，不粗暴杀掉活跃请求。
3. 将新程序放入独立版本目录，保留旧程序/配置。按确认的部署机制原子切换；不直接覆盖正在执行的文件，不使用未核实的递归删除。
4. 按实际服务单元或固定镜像重启，仅操作目标应用，不连带重启共享数据库或 Redis。
5. 观察启动日志及迁移结果；失败立即停，不让后续节点继续升级。
6. 在批准的节点入口检查 /health、版本、公开设置、静态 HCAI 资源、数据库/Redis连接和节点指标；/health 200 不是完整业务验收。
7. 少量回流，按发布单观测错误率、P95 延迟、流断开、内存、连接池、队列、审核节点与后台任务心跳。
8. 达到事先约定的量化门槛和观测时间才恢复正常流量并推进下一台，记录 SHA、校验、时间和结果。

请求生成、支付或真实上游探测需明确授权；未授权时只做不扣费检查并列出业务验证缺口。不为“测试部署”随意禁用真实用户 Key 或修改线上渠道价。

## 6. 迁移与灰度边界

发布前在备份恢复出来的独立环境验证全部待执行迁移。先检查新增/删除字段、索引回填、锁表时长和旧程序兼容；不能只按迁移编号推断顺序或去重。

首次升级节点可能在启动路径执行迁移，必须确认实际启动行为、迁移锁和记录。先启动一个节点观察迁移完成再滚动其他节点；没有独立迁移 CLI 的证据时，不编造手工命令。

共享数据库已迁移会影响未升级区域。若破坏旧版本兼容，禁止常规多版本滚动，改为经批准的维护窗口、停写/摘流方案或先发兼容过渡版本。

## 7. 集群验收

- 所有目标节点显示同一目标版本与 SHA，node_id 唯一、region 和配置角色正确。
- 首页正常加载不闪旧页，资源失败回退符合当前代码；中英文无裸翻译 key。
- 插件开关保存后刷新仍有效，授权范围内验证。
- 模型广场渠道展示价、官方参考价及扣费边界没有混淆。
- 全局作业有健康候选且不会因独立 Redis 每区重复执行；OAuth 刷新和任务无异常积压。
- 使用专用测试 Key 验证跨区域禁用传播，记录目标时延；不承诺自动等于测试脚本的 30 秒阈值。
- 检查支付回调、对象存储、图片结果读取及错误日志，涉及真实资金操作必须走单独批准的测试单。
- 所有节点上线后检查总容量、错误、费用和异步积压，发布单留存观测结果。

## 8. 回退与灾难恢复

出现迁移失败、认证失效、计费异常、持续错误率/延迟超阈值或重复扣费/重复任务，立即暂停后续区域，摘除问题节点并通知负责人。

数据库向后兼容且旧配置可用时，切回已验证的旧程序/镜像，重启、验收、回流；保留异常日志和新旧产物。不能移动 Git 标签冒充回退。

数据库不兼容时不能只换旧程序；优先前向修复，或在批准的停写窗口统一恢复数据库和匹配程序。共享数据库恢复影响所有区域且可能丢失新订单/用量，必须核对恢复点、支付/返利一致性及数据补偿。未经批准不执行 DROP、清空 Redis 或全库恢复。

日本任务区域故障时，先确认旧 leader 无法继续工作并进行隔离，再按预案让备用区域参与任务选举，验证无双执行；不要盲目同时开启所有区域。

## 9. 多区域测试环境

[仓库测试环境](../../deploy/tests/multiregion/README.md) 只有日本两节点、台湾一节点、美国一节点，不覆盖生产第三日本节点。run.sh 会构建/创建临时环境、调用真实上游产生费用、写测试数据、模拟 kill，并默认销毁临时卷。仅在授权的隔离环境执行，绝不将配置指向生产数据库/Redis。

HCTOPUP_API_KEY 由秘密管理环境注入，不写脚本或命令历史。KEEP_ENV=1 可保留测试环境供排查，需安排清理并保护其中凭据。该脚本的通过结果不能代替真实生产入口、容量或发布审批。
