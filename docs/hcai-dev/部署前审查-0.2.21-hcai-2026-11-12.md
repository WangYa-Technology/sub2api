## 数据库迁移与新旧节点混跑

从 v0.2.20-hcai 到本版本新增两份 SQL，历史迁移未被删除或修改；按完整文件名识别，同编号文件可共存。

| 迁移 | 作用 | 部署影响 |
| --- | --- | --- |
| 249_add_usage_logs_api_key_cost_index_notx.sql | usage_logs(api_key_id, created_at) INCLUDE(actual_cost) 并发索引 | 需要额外磁盘、IO；长事务可能延迟完成；并发构建不等于完全无资源/锁影响 |
| 250_openai_cache_write_ttl.sql | usage_logs 新增默认 0 的 30m/12h token 字段；四个渠道价格表新增 nullable 12h 价格字段 | ALTER TABLE 仍需获取表锁；没有删除/改名旧字段，无数据回填脚本 |

**自动迁移正常存在。** `backend/internal/repository/ent.go:136` 在正常 InitEnt 启动路径建立 10 分钟上下文，调用 applyMigrationsFS。迁移 runner 使用同一数据库会话的 PostgreSQL advisory lock 串行执行，按完整文件名和 checksum 记录。`_notx.sql` 在事务外执行；249 有无效索引清理后重试处理。完成后后续节点检查记录并跳过已应用项。

注意该 10 分钟是当前正常启动代码的实际期限，不是任意可配置的启动等待承诺；systemd 等外部超时也须核对。首次启动应等迁移日志，不用短时间无 HTTP 响应直接判失败。索引超时或 ALTER 等锁失败时先确认数据库状态，不盲目重复重启所有节点。

此前 PostgreSQL17 隔离环境全量迁移成功，但不是生产数据副本。源码结构上是兼容性新增，支持旧版短时混跑；旧节点不会记录新的缓存 TTL 字段，滚动期间新旧节点的计费/统计能力可能不同，应缩短混跑窗口。本轮没有实际混合版本生产压测，不承诺完全等价。

回切旧二进制在结构上无需撤销新增字段/索引；旧版仍不具备新缓存 TTL 语义。若发生计费异常，需先保留用量证据，不能用数据库回滚抹去业务数据。

## 需要留意的上游行为变化

1. OpenAI 30m/12h 缓存写入新增统计和单独价格。显式 cache_write_12h_price 时分开计费；已有显式通用 cache_write_price 且未设置 12h 时保持平价，不强加官方 12h 倍率。无渠道覆盖时可能采用目录的 TTL 价格，属于上游功能变化。无效 TTL 明细回退汇总逻辑。相关定向测试本轮通过。
2. 内置 Sonnet 5.5 fallback 缓存读取价格由 0.2e-6 改为 0.1e-6；实际采用目录还是渠道覆盖取决于现有配置，不宣称所有模型原价不变。
3. 未显式设置请求体内存预算时，改为可检测内存上限的 1/4、最低 1GiB；检测包括物理内存、systemd/cgroup 和 GOMEMLIMIT。预算不是启动预分配，也不是进程总内存硬上限。小机器最低仍为 1GiB（与旧默认相同）；大机器默认可能提高，需要观察 RSS/并发请求。显式配置保持原值，0 表示禁用该限制，不推荐为上线临时关闭保护。
4. 本次上游协议/调度/生图修改不代表已解决此前 GIF 上游拒绝问题，不以本轮审查授权真实付费调用。
