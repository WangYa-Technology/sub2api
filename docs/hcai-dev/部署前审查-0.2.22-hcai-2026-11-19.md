## 功能与 HCAI 定制影响

0.2.22 上游变更包括 UltraFast 倍率（Sol 由 2 到 6）、Vertex 默认价格/区域路由、按用户批结算及汇总重建；这些涉及真实计费和调度，不能当作纯工程升级。[合并记录](上游合并记录-0.2.22-hcai.md)逐项确认 HCAI 首页、插件开关、模型广场展示价优先但实际扣费独立、双语、菜单凭证隔离、CC Switch、支付沙箱/返利、图片存储和多节点锁等仍保留。PR #59 未修改应用目录；其自动化配置不会进入旧 Release 二进制。

既有 TLS 模板 Transport 热更新缺口仍未解决；历史 usage 超时及美国 scheduler 重建超时不能因本次上游优化而视为已修复。真实生产模型、支付、插件和跨节点设置行为未在本次审查中重测。

## 增量审查：上游 issue #8930（2026-11-19）

[上游 issue #8930](https://github.com/Wei-Shaw/sub2api/issues/8930) 报告 GPT-6.2 的 Responses API 顶层 `instructions` 不参与前缀缓存。[OpenAI 文档](https://developers.openai.com/api/docs/guides/keep-prefix-unchanged)明确建议将可复用开发者指令放在 `input` 首个 `developer` 消息；GPT-6.2 起顶层 `instructions` 追加在 `input` 后，按未缓存输入计费。issue 中 v0.2.23 的外部实测报告：省略该字段时普通 OAuth 路径多出约 5.4k 输入 token；这不是 HCAI 生产环境的实测值。

本地静态核对 `v0.2.22-hcai` 对应应用代码：`openai_gateway_forward.go` 在 OAuth/SetupToken 普通 Responses 转发且 `instructions` 缺失或仅空白时注入 `defaultCodexSynthInstructions(upstreamModel)`；`openai_codex_transform.go` 也会把 `system` 文本提升至顶层，并在空值时填入默认指令。0.2.22 未内置 GPT-6.2 Sol/Astra 模型映射和专属提示词，因此不能称该版已正式支持 GPT-6.2；但未知模型名可保留原值转发，若手动开放该模型、上游接受请求且使用上述普通 OAuth 路径，仍可能触发相同的未缓存输入成本。原生 API Key 的 Responses 转发不走这段默认注入。OAuth 透传仅在请求模型名包含 `codex` 且字段不存在时注入默认指令；`gpt-6.2-sol`/`gpt-6.2-astra` 不满足该条件。issue 对透传有互相矛盾的现场描述，当前代码条件与上游 v0.2.23 标签一致，实际账号/模型/出站请求仍待核验。Messages 兼容路径的强制指令模板也可能设置顶层字段，需按实际配置判断。

影响判断：目前没有证据表明 0.2.22 既有 GPT-6.1 等模型发生功能错误，也没有 HCAI 定制代码被此 issue 直接破坏的证据；主要是 **GPT-6.2 在特定转发路径下的缓存命中与计费风险**，可能间接影响 HCAI 的真实扣费、展示价格与客户成本核对。它不改变上文 0.2.22 部署阻断结论。对计划中的 0.2.23-hcai，因上游已正式加入 GPT-6.2 映射，合并/发布审查须增加出站请求体、`cached_tokens` 和实际计费对照；未完成前不放行 GPT-6.2 OAuth 普通转发对外使用。可暂时不开放 GPT-6.2；修复方案应在明确上游协议要求后评审和回归，不能仅凭 issue 建议直接改写指令位置。此次只做源码与公开证据核对，未连生产、未发付费请求、未修复业务代码。
