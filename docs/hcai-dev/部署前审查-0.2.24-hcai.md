## 问题一：上游改了什么

新增 Exa 搜索模拟供应商、原生 ToolSearch、搜索来源返回、元数据驱动的 Anthropic 长上下文目录和模型广场 ID 复制。修复 buffered/streaming 协议重建、Kimi 动态工具/stop、DeepSeek 工具历史 thinking、Gemini 工具结果/SSE 注释、System One 模型映射、OpenAI 超时换号、OAuth 轮换后凭据保存竞态、外厂模型排除、alpha/search 403 误隔离及 Antigravity 裸 429 误冷却/自定义额度端点。优化请求扫描/保留内存、调度缓存 payload、用量刷新；普通用户默认平台配额扩展到后台创建路径。

网关对重复/歧义字段增加拒绝：JSON 相同值重复也拒绝，支持大小写/转义/嵌套及 multipart/WS，防止准入、实际转发与计费选到不同字段。详情和变动路径见[合并记录](上游合并记录-0.2.24-hcai.md)与[净差异](上游净差异清单-0.2.24-hcai.md)。本段依据固定源码和提交历史；未通过生产请求验收。

## 问题二：对功能有什么影响

- 部分原来接受的歧义请求返回 400，JSON Schema/工具参数自由命名空间仍保留合法大小写不同字段；新限制可能暴露旧客户端的重复序列化问题。入口 body limit 与读取/WS 校验均有改动，需覆盖所有协议和图片别名。
- Grok 原生搜索有 usage.server_side_tool_usage_details 时以成功计数计费，缺失时按输出项回退；Claude Code compaction 写入用 5m，普通缓存注入及账户级覆盖仍各按原规则。默认用户配额、模型可选目录、重试/冷却与每轮 reasoning 记录影响请求可用性或真实费用，不能宣称只改展示。没有修改 HCAI 支付/返利资金写入。
- 运维 Token 速率从请求速率算术平均改为按有效请求耗时加权；长短请求混合时展示值会变化，不是模型价格变化。HCAI 保留数据库缓存/全局计算锁，本轮额外隔离 v2 缓存键，避免混版本互相返回旧口径。
- 账户窗口成本是估算；新增刷新键、频繁手动刷新警告和批量模型过滤独立勾选，警告不阻拦操作。模型广场可复制真实 ID，币种/官方价来源没有被复制操作改变。

## 问题三：对 HCAI 定制行为有什么影响

首页品牌/loading/主题、插件开关的保存/读取/公开门控、渠道展示优先且实际扣费默认分组优先、独立美元官方价/人民币汇率、菜单凭据隔离、CC Switch 四模式、支付宝沙箱/兑换码返利、WeCom、MinIO 与异步图片 RequestType=6、节点身份/后台任务锁、OAuth 共享 DB 租约、认证 outbox 和设置缓存失效链路保留。依据为两侧差异与未变保护路径的字节比较、30 条交叉路径审查，非线上全功能验收。

发生交叉的关键路径为网关用量/异步类型、GPT-6.2 developer 稳定指令、OAuth CAS/租约、统计 SQL/共享缓存和 WebSearch 配置广播。已修复统计 v1/v2 混用问题，以及 DB-only OAuth 路径未预留 detached 落库时间的问题；两项新增回归均尚待提交步骤执行。其他已识别保护点未发现需丢弃定制的理由。测试尚未执行的部分均列为验证门槛。既有 TLS Transport 复用缺口保留为已知风险：模板快照同步不保证已缓存 Transport 使用新指纹；见[历史边界证据](四类运行时缓存多节点一致性修复-2026-11-14.md#同日功能影响复核tls-transport边界)。本轮未触及该 Transport 实现，不能把模板测试视为握手热更新已通过。

## 迁移与配置

无本轮新增或改写 SQL、索引/回填、依赖锁或必填环境变量。逐完整文件名确认旧 HCAI 317 个、上游 305 个 SQL 均原样保留（12 个 HCAI 专有 SQL）；历史 checksum 不重写、不按编号去重。对已有部署仍需核对 schema_migrations 的完整 filename/checksum、实际落后版本、迁移锁和可恢复备份；不能因本轮无迁移就宣称生产无需迁移。

Wire 生成文件增加 NewAdminService 已有平台配额仓储参数，源 ProviderSet 和 HCAI KV/租约/清理链路保留。所有调用参数数量已静态核对，实际生成/编译待提交步骤。

Exa 存在已有 web_search_emulation_config JSON 内。混版本时禁止启用 Exa：旧版不识别 type，会在 Manager 的默认分支回退 Brave，不能用 Exa 凭据交给旧节点尝试。所有节点升级且配置传播验收后才可按授权启用；回退前必须先用新版将供应商改回旧版支持的配置。无须为了合并修改线上配置。

## 混版本与回退

- 旧 HCAI 与候选均保留共享 PostgreSQL OAuth 租约及区域 Redis 兼容锁；必须核实所有节点使用同一权威 DB、正确 Redis scope/稳定密钥和节点角色。已轮换 token 不可逆；回退不能恢复旧 refresh_token 或历史账号表来覆盖新凭据。新 CAS、取消落库和故障遏制需要隔离测试。DB-only 路径现与 Redis 路径一样从默认 60s 租约预留保存/清理预算，执行不超过 41s；19s 等过短租约在消耗轮换 token 前拒绝并释放租约，新增 sqlmock 回归未执行。
- 新旧统计结果分别 v2/v1，120s 过期后自动清理；全局 advisory 计算锁保持同一命名空间，因此继续互斥扫描。回退旧程序保留缓存表和 v2 行，无需删表、清 Redis 或修改迁移记录。首次 v2 读取为冷缓存，观察 DB IO/等待和 503，隔离测试尚待执行。
- 调度 payload 不再展开分组对象但保留成员 ID/优先级；共享 Redis 的旧 reader 及回滚读写兼容仍需实际回归。已有会话/在途搜索不强制切换；新的歧义拒绝仅在新节点生效，灰度期间客户端可能观察不同响应。
- 支付、返利、异步图片、对象存储及认证广播必须跨节点核对，保留已验证的上一版 HCAI 产物、配置和共享存储；发现错账/租约竞争/任务重复/持续异常立即停止后续节点。回退二进制前排空 WS/流式及任务，使用已授权节点清单，不把历史拓扑当当前部署指令。
